# Intro

This file contains helpful information when configuring clang-tidy.

For the different options for name style checks see:
https://github.com/llvm-mirror/clang-tools-extra/blob/8eb332109a2c68f791eda33fe28f174e77bbc5fe/clang-tidy/readability/IdentifierNamingCheck.cpp#L66

## 2018-08-19
These are the name styles that where supported at this date.
 * lower_case
 * UPPER_CASE
 * camelBack
 * CamelCase
 * Camel_Snake_Case
 * camel_Snake_Back
 * aNy_CasE

## Generated `.clang-tidy`

At startup, unless a local `.clang-tidy` that was not generated by code_checker
exists in the working directory, code_checker writes a `.clang-tidy` there. It
is derived from the system configuration set by `[clang_tidy] system_config`
(default: `etc/code_checker/clang_tidy.conf`):

 * The system configuration is parsed as YAML (the vendored dyaml package).
   The values of `HeaderFilterRegex` / `ExcludeHeaderFilterRegex` are replaced
   with the configured `clang_tidy.header_filter` /
   `clang_tidy.exclude_header_filter` when those are set; a set filter whose
   key the system configuration lacks is appended to the generated file, with
   a warning. A filter value that contains a single quote or ends with a
   backslash is ignored instead: it is neither substituted in place nor
   appended, the base line passes through and a warning is logged.
 * When `[static_code] severity` is set, the checks that the severity filter
   disables are spliced into the `Checks` value: one list element per check
   (base entries are split on commas), e.g.
   `Checks: ['-*', 'clang-diagnostic-*', ...]`. Relative to the `.clang-tidy`
   the previous generator produced, the set of checks is unchanged; only the
   YAML layout of a multi-line quoted `Checks:` block collapses to a single
   line. A `[static_code] severity` set while the system configuration has no
   `Checks` entry is not applied either; a warning is logged.
 * If the system configuration cannot be read or parsed, or its root is not a
   mapping, its content is used as-is for the generated `.clang-tidy`
   (verbatim, as far as the file is readable as text) and a warning is logged;
   the filter and severity settings above are not applied.

The generated file starts with a `# GENERATED by code_checker` comment. A local
`.clang-tidy` without that comment is used as-is and is never overwritten; the
filter and severity options do not work with such a local config.
